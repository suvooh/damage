The phone does the work by default. The server checks only the cases where the phone is unsure, the photo is borderline, or the part is safety-critical.

2The six models

Each use case has one model pair. The server model is trained first. The phone model is then trained to copy it (distillation), so it stays small but close to the server model's accuracy.

Use casePhone modelServer modelFinds
1 ExteriorLightweight instance segmentation (RTMDet-Ins-S class, Apache 2.0); 10–25 MB; < 2 s per photoMask2Former + DINOv2 ViT-L; GPUPanels: doors, bumpers, bonnet, fenders, quarters, boot, roof, lamps, glass. Damage: scratch, dent, crack, paint damage, missing part
2 InteriorSame model type, own trainingMask2Former + DINOv2 ViT-LComponents: dashboard, instrument cluster, seats, door trims, console, steering wheel, headliner. Damage: tear, stain, crack, scratch, burn, broken part
3 UndercarriageSame model type, own trainingMask2Former + DINOv2 ViT-LComponents: shocks, springs, control arms, CV boots, exhaust, oil pan, brake and fuel lines. Damage: leak, corrosion, torn boot, bent part, crack, impact mark
Undercarriage is always advisory. It reports visible damage only. Any finding on steering, brakes, suspension or structure is flagged for a technician, and the system never certifies that a car is mechanically sound.

4Training pipeline: server models → phone models

For each use case, the bigger server model is trained first. It then labels photos for the small phone model, which learns to copy it (distillation). Three use cases means this runs three times.

Starting settings

SettingServer model (bigger)Phone model (small)
ArchitectureDINOv2 ViT-L/14 backbone + Mask2Former decoder; two heads (parts, damage)Lightweight instance segmentation (RTMDet-Ins-S class); two heads (parts, damage)
Size~330 M parameters, ~650 MB (FP16)~10 M parameters, 10–25 MB (INT8 / FP16)
Input1,024 px photos + 1,024 px tiles from full-resolution photos1,024 px (exterior), 768 px (interior, undercarriage)
Training stagesA2: decoder only, ~20 epochs → A3: full fine-tune, ~50 epochs~120 epochs of distillation, then ~10 epochs of quantisation-aware training
Learning ratesAdamW; 1e-4 decoder, 1e-5 backbone with layer-wise decay 0.9AdamW or SGD; 1e-3 with cosine schedule
LossesMask: cross-entropy + Dice; class: focal. Thin damage (scratches): extra Dice weightGround-truth loss + teacher-matching loss on masks and scores
Hardware8 × A100 / H100 GPUs; about 1–3 days per use case1–2 GPUs; under 1 day per use case
OutputServer model + thresholds per damage typeSigned phone model files for iOS and Android

Epochs, sizes and training times are starting estimates. Tune them on the first dataset version of each use case.

9What the report shows

One report per vehicle, with a section for each use case that was inspected. Every damage lists its part, type, size, severity, confidence, and whether the phone or the server produced it.
